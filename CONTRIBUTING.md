# Contributing to AIPulse

## Building

### Prerequisites
- macOS 14 or later
- Xcode command line tools: `xcode-select --install`
- Node.js 18+ (for ccusage)

### Build and Install

```bash
git clone https://github.com/chuchy4ever/AIPulse.git
cd AIPulse
./install.sh
```

This builds the app and installs it to `/Applications/AIPulse.app` with launchd job and scripts.

### Build Only (Without Installation)

```bash
swift build -c release
```

Output: `./.build/release/AIPulse` (executable)

## Code Style

- **Language:** English for identifiers, class/function/variable names, comments
- **File organization:** `.swift` files in `Sources/AIPulse/`
- **Comments:** Explain *why*, not *what*. Assume the reader understands Swift
- **Text and UI strings:** Use `L.t("key", language)` from `Localization.swift`. Never hardcode user-facing text
- **Numbers and formatting:** Keep locale-aware formatters in `AppState` methods (`formatTokens`, `formatYAxisLabel`, etc.); call them from views

## Localization

All user-visible strings go through `L.t()`:

```swift
L.t("settings.title", config.language)
L.t("error.data_load_failed", language)
```

Strings are defined in `Localization.swift` as `[String: String]` dictionaries for each language (`cs` and `en`). Add both languages when adding a new key.

## Screenshots

`docs/popover.png` is produced by the app itself, not captured from the screen:

```bash
/Applications/AIPulse.app/Contents/MacOS/AIPulse --snapshot docs
```

It renders the popover offscreen at 2x with `ImageRenderer` and exits. Regenerate
it whenever the popover changes rather than taking a new screenshot by hand.

Only the popover is rendered, and only the popover can be: `ImageRenderer`
refuses anything AppKit-backed - `NavigationSplitView`, a segmented `Picker`,
`ProgressView`, `ScrollView` content - and draws a yellow placeholder block
instead, so the settings panes need a real screen capture. Snapshot mode also
skips the service watcher, so taking a picture never writes state or raises an
alert.

## Runtime Data

These files are generated at runtime and must never be committed:

```
~/.local/share/aipulse/
  data.json          — collected usage (generated by collect.sh)
  config.json        — user settings
  collect.log        — debug logs
  *.log              — launchd output/error
  .tmp.*             — scratch files during collection
```

These live outside the repository, so `.gitignore` never sees them. What it does
cover is a stray `data.json` or `config.json` left inside a working copy.

## Testing

Swift code is tested via `swift test` (when test suite exists). Shell scripts (`scripts/*.sh`) should be validated for syntax:

```bash
bash -n scripts/collect.sh
bash -n scripts/refresh-limits.sh
bash -n scripts/set-interval.sh
python3 -m py_compile scripts/login.py
bash -n install.sh
```

End-to-end: install locally, check menu bar displays, verify data file updates every N minutes.

## Submitting Changes

1. Fork and create a feature branch
2. Make changes to `Sources/` only; scripts and Package.swift are shared
3. Test: `./install.sh` and verify app runs and data loads
4. Commit with clear messages (English, imperative mood: "Add chart type selector")
5. Push and open a pull request

## Architecture Notes

- **AppState:** manages data load/save, config, bar display logic, theme colors, aggregations
- **Models:** Swift `Codable` structs mirroring `data.json` schema
- **Views:** SwiftUI components; hierarchy is PopoverView → sections, with the menu bar item itself drawn in `AppDelegate`
- **Localization:** `L.t()` bridges `config.language` and string dictionaries
- **Scripts:** `collect.sh` does all external I/O (ccusage, curl, Python); app is read-only
- **Limits:** fetched via OAuth token from Keychain (set by Claude Code); cached in data.json

## Privacy and Security

- App reads local files only; no telemetry or remote logging
- OAuth token never written to disk or logs; sourced from Keychain each time
- Service status fetched from public status pages (status.claude.com, status.openai.com)
- User config and collected data stay on disk in `~/.local/share/aipulse/`

Respect this boundary: don't add remote logging, analytics, or crash reporting without explicit user consent.
